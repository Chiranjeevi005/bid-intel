# UI DESIGN SYSTEM v1.0

Status: LOCKED
Version: 1.0
Purpose: Permanent product UI and branding foundation

---

## 1. Design Identity

Editorial Intelligence × Modern B2B SaaS

The product must feel like serious procurement intelligence
infrastructure, not a generic AI application.

Design priorities:

1. Trust
2. Evidence
3. Risk visibility
4. Decision support
5. Professional efficiency

The interface must communicate intelligence through clarity,
hierarchy, evidence, and information design rather than decorative
AI aesthetics.

---

## 2. Visual Direction

Reference character:

- Linear
- Vercel
- High-end editorial products
- Professional data/intelligence applications

The product is:

- Light-first
- Clean
- Dense but readable
- Evidence-centric
- Professional
- Restrained
- Information-rich

The product is NOT:

- A generic AI dashboard
- A futuristic AI interface
- A marketing-heavy SaaS dashboard
- A glassmorphism interface
- A neon interface

---

#0F172A

Purpose:
- Primary text
- Navigation emphasis
- Strong headings
- Structural UI elements

### Risk States

Critical:
#DC2626

Review Required:
#D97706

Covered:
#16A34A

### Rules

- No gradients.
- No neon colors.
- No decorative color usage.
- Colors must communicate state or hierarchy.
- Risk colors must never be used decoratively.

Primary Font:

Inter

Typography must prioritize:

- Readability
- Numerical clarity
- Evidence readability
- Dense information scanning
- Professional hierarchy

### Scale

Display:
32–40px / 600

Page Heading:
24–28px / 600

Section Heading:
16–18px / 600

Body:
14–15px / 400

Metadata:
12–13px / 500

Evidence Quote:
14px / 400

Evidence text should use generous line height.

Numerical data should use tabular numerals where appropriate.

## 5. Layout System

The application uses a professional workspace layout.

Primary structure:

Navigation
→ Document
→ Intelligence
→ Evidence

The document and evidence remain the center of gravity.

Avoid excessive dashboard-card layouts.

Prefer:

- Tables
- Structured sections
- Compact information blocks
- Evidence panels
- Clear hierarchy
- Consistent spacing

---

## 6. Component Language

### Borders

Use thin, subtle borders.

### Shadows

Use restrained shadows only where hierarchy requires elevation.

### Radius

Default radius:
6–8px

Avoid highly rounded cards and excessive pill-shaped components.

### Density

The application should be information-dense without becoming visually crowded.

Use whitespace to separate conceptual groups rather than large decorative gaps.

---

## 7. Evidence UX

This is a core product principle.

Every important AI conclusion must provide an immediate path:

Finding
→ Severity
→ Fact
→ Quote
→ Page
→ Source

The user must never have to search through the document manually
to understand where an important conclusion came from.

---

## 8. Critical Coverage UX

The following rule is mandatory:

NO VERIFIED FINDING ≠ NO REQUIREMENT

Coverage states:

### COVERED

A verified finding exists and relevant evidence was examined.

### REVIEW_REQUIRED

Relevant evidence was detected, but no verified finding survived
extraction/recovery.

### EXTRACTION_UNCERTAIN

There is insufficient evidence coverage to safely conclude whether
the requirement exists.

The UI must make REVIEW_REQUIRED and EXTRACTION_UNCERTAIN highly
visible.

Never display absence of a finding as proof of absence of a requirement.

---

## 9. Risk Communication

Critical:
Red

Review Required:
Amber

Covered:
Green

Risk states must always include text labels.

Never rely on color alone.

---

## 10. Navigation

Navigation should remain minimal and purposeful.

Primary application areas:

- Documents
- Intelligence
- Evidence
- Settings

Future areas may be added only when they represent a genuine
workflow requirement.

---

## 11. Animation

Animation must be functional rather than decorative.

Allowed:

- Loading states
- Progress transitions
- Expand/collapse
- Page transitions
- State changes

Avoid:

- Excessive motion
- Decorative animations
- Animated gradients
- AI "thinking" effects
- Distracting transitions

---

## 12. Forbidden Design Patterns

The following are permanently prohibited unless this design system
is explicitly revised:

- Glassmorphism
- Neon UI
- Excessive gradients
- Decorative AI effects
- Excessive pill components
- Giant dashboard cards
- Cartoon illustrations inside the application
- Futuristic AI visual clichés
- Excessive rounded corners
- Rainbow status systems
- Decorative animations
- Unnecessary visual complexity

---

## 13. Branding Principle

The product should feel like:

Trustworthy procurement intelligence.

Not:

AI magic.

The visual identity must reinforce:

Evidence
→ Intelligence
→ Risk
→ Decision

---

## 14. Screen Consistency Rule

Every future screen must inherit this design system.

This includes:

- Landing page
- Login
- Signup
- Document upload
- Processing
- Document list
- Intelligence report
- Risk analysis
- Evidence viewer
- Coverage dashboard
- Settings
- Billing
- Admin interfaces

Individual screens must NOT introduce independent visual systems.

---

## 15. Change Control

This document is LOCKED.

Any future design change must:

1. Identify the problem with the current system.
2. Explain why the existing rule is insufficient.
3. Demonstrate the proposed improvement.
4. Update the version number.
5. Explicitly mark the previous version as superseded.

Do not introduce visual changes merely for novelty.

---

## 16. Core Design Rule

When in doubt:

Choose clarity over decoration.
Choose evidence over aesthetics.
Choose hierarchy over complexity.
Choose trust over novelty.
Choose professional usability over visual trends.
